# profile/ —— 账号档案

两个文件：

| 文件 | 是什么 | 进 git 吗 |
|---|---|---|
| `voice.md` | 语气档案（分模式） | ❌ 已 gitignore，见下 |
| `cover.json` | 封面配色预设 | ✅ 只是颜色，没隐私 |

---

## cover.json —— 封面配色预设

固定的部分放这里，**不用每次敲**：

```json
{
  "style": "zine",
  "tone": "ivory",
  "accent": "cobalt",
  "sig": "@vivian"
}
```

`render_cover.py` 会从当前目录往上找这个文件。命令行参数优先级更高。

**锚形状（`--anchor`）刻意不放进预设** —— 它必须每篇按主题重新想，
固定下来就失去意义了。配色固定是为账号辨识度，锚变化是为内容表达。

## voice.md

这是整个仓库最重要的一个文件。`xhs-note`（写）和 `xhs-polish`（改）
每次开工前都会读它。

**没有它，写出来的东西一定不像你** —— 模型对「小红书博主」的默认印象是
`✨氛围感拉满✨`、`姐妹们冲`、`值得一提的是`。档案的主要作用是**把这个默认关掉**。

### ★ 档案是分模式的

这个账号有两种内容 —— **科普/信息型**和**生活/日常型**，写法不是同一套。
科普稿里 emoji 当项目符号是对的，生活稿里同样密度就变成模板号了。

所以 `voice.md` 分成：模式 A（科普）、模式 B（生活）、共同底线。
写稿之前**先定模式**。

出现第三种内容（恰饭稿、测评）就再加一个模式，不要硬塞进现有的。

### 怎么生成

1. 把你发过的笔记放进 `samples/`，**按类型分子目录**（`samples/guide/`、`samples/life/`）
2. 跟 agent 说「学一下我的语气」
3. 生成 `profile/voice.md`，然后**验收一下**（它会问你几个具体问题）

没有历史笔记就走问卷冷启动：`skills/xhs-voice/references/questionnaire.md`。

看 `voice.example.md` 了解档案长什么样 —— 那份的科普模式是从一篇真实笔记提的，
生活模式**故意留空**，因为还没有样本。

> **样本不足时留空比填满更有价值。** 一份标着「生活模式：无样本，以下 9 个问题
> 答不了」的档案是诚实可用的；凭空编满会让每篇生活稿都错，而且错得很自信。

## ⚠️ voice.md 默认不上传

`.gitignore` 里有一行 `profile/voice.md`。

原因：**这个仓库是公开的**（github.com/heyisvivian/-agent），
而 voice.md 里会有你笔记的原文引用、写作习惯分析、甚至「我不用感叹号」
这类挺私人的观察。放到公开仓库里等于把你的写作指纹公开了。

**想在多台机器之间同步**的话，两个选择：

- 把 `.gitignore` 里的 `profile/voice.md` 那行删掉（仓库改成 private 更好）
- 或者手动拷这个文件，不走 git

---

## 档案要维护

你的风格会变。

- **每积累 10 篇新笔记** → 放进 `samples/` 重跑 `xhs-voice`，看统计有没有漂移
- **你说「这个不像我」的时候** → 不要只让 agent 改那一篇，
  要把结论写回档案。**一次这样的反馈价值大于十篇样本。**
- 开始接商业合作后 → 恰饭稿的语气可能和日常不一样，在档案里单独开一节

---

## 档案里最有用的部分

是**「绝对不是她」那个反例清单**，不是「她是什么」。

「她克制、真诚、有细节」——这种描述模型没法执行。
「不用感叹号、不用『姐妹们』、结尾不升华」——这个能执行。

所以写档案和维护档案时，多往反例清单里加东西。
