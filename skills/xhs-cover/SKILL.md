# xhs-cover —— 封面图

## 分工原则（这是这个技能的核心设计）

| 做什么 | 谁做 | 为什么 |
|---|---|---|
| 背景、氛围、场景、质感 | **`image_gen`**（Codex 内置） | 走 ChatGPT 订阅，不需要 API key |
| **中文标题文字** | **本地 HTML/CSS 渲染** | AI 出图写中文经常缺笔画、错字、字距乱 —— 封面标题是要被人读的，不能赌 |

不要让 `image_gen` 直接把中文标题画在图上。生成十次有八次得重来，
剩下两次字距也不对。**背景归 AI，文字归渲染器。**

---

## 风格：zine 极简杂志风（默认）

视觉体系参考 [gc-minimal-zine-poster](https://github.com/LiamGvchi/gc-minimal-zine-poster)
的 style-system：**纸纹负空间 + 单一高彩度锚色 + 安静的衬线／打字机字 + 印刷缺陷**。
调性是日韩独立 zine / 极简编辑设计，明确避开商业广告感、光泽感、电影感、3D、霓虹。

完整规则见 `references/zine-style.md`。

### ⚠️ 一处必须知道的差异

原版是 **3:5 海报、留白 70–90%、"文字像便条而不是广告标题"**。
小红书封面是 **3:4**，而且**要在信息流缩略图里被看清**。
完全照搬会让标题在 feed 里小到读不出来，点击率会掉。

所以：

| | 留白 | 标题字号 | 适合 |
|---|---|---|---|
| `zine` ★默认 | 约 60% | 88–100px | 大多数情况。仍然安静，但缩略图里读得清 |
| `zine-pure` | 75%+ | 约 62px | 忠实原版比例。好看，但靠封面抓陌生人时吃亏 —— 适合已有粉丝基础 |

**新号或想涨粉时用 `zine`。** 想要那种"我不在乎流量"的气质时用 `zine-pure`。

## 三条路线

### 路线 A · 纯文字 zine 封面（最快，最稳）★ 推荐起点

不需要 `image_gen`。zine 风格本来就是负空间为主，没有照片完全成立。

```bash
python skills/xhs-cover/scripts/render_cover.py \
  --title "京都下雨那天|我什么都没干" \
  --label "travel [03]" \
  --caption "一个人旅行 · 第 3 天" \
  --micro "kyoto 2026.08" \
  --sig "@vivian" \
  --out drafts/2026-08-13-kyoto/cover.png
```

### 路线 B · 她自己的实拍照，装进 zine 窗口

真实照片的点击率高于任何生成图。`zine-photo` 把照片装进不出血的窗口，
去饱和、压网点、叠一层锚色油墨 —— 照片进入 zine 的印刷体系，而不是突兀地贴上去。

```bash
python skills/xhs-cover/scripts/render_cover.py \
  --title "京都下雨那天|我什么都没干" \
  --label "travel [03]" --caption "一个人旅行 · 第 3 天" \
  --bg her-photo.jpg --style zine-photo \
  --out drafts/2026-08-13-kyoto/cover.png
```

### 路线 C · `image_gen` 出背景

她没有合适照片时用。

**第 1 步**，用内置 `image_gen` 生成，存到 `drafts/<日期>-<slug>/cover-bg.png`：

- 尺寸要 **3:4 竖版**。优先 `1152×1536`（3:4 且两边都是 16 的倍数）。
  工具不接受就退到它支持的任意竖版尺寸 —— 渲染器用 `cover` 裁切，比例不对只裁掉一点边。
- **prompt 里绝对不要写任何要出现在图上的中文文字。**
- 内置工具默认存到 `$CODEX_HOME/generated_images/`，**记得移到 drafts 目录里**。

**第 2 步**，压字（同路线 B 的命令，`--bg` 换成生成的图）。

**第 3 步**，把用过的 prompt 存到 `drafts/<日期>-<slug>/imagegen.md`，方便复现。

## image_gen 的 prompt 怎么写

按原版 prompt-compiler 的**四段结构**，一段一件事：

```
① 画布、纸色、负空间比例、视觉簇位置
② 视觉隐喻、锚的形态、材质处理
③ 主色、色彩载体、印刷缺陷
④ 扫描纸张的调性 + 要避开的东西
```

核心原则（原文）：**"Prefer one concrete visual decision over several vague aesthetic labels."**
—— 一个具体的视觉决定胜过一堆模糊的美学标签。以及
**"Keep the event isolated and imageable; do not expand it into a full scene."**
—— 事件要孤立、可成像，不要扩展成完整场景。

### 例子（给 zine-photo 的窗口用）

```
竖版 3:4，暖白纸张满幅，纸纤维和细颗粒可见，约 78% 留白，
视觉簇在中央偏下，占画面约 18%。

一扇京都民宿的木格窗，窗台上一只小茶杯，孤立的单一物件，
不要延展成完整室内场景。平面正投影扫描感，漫射光，低对比，无硬阴影。

灰度成像为主，唯一高彩度锚色是钴蓝，只出现在茶杯上，占画面约 1.5%。
半调网点、xerox 柔化、轻微套印偏移、纸张边缘缺陷。

安静、诗性、像旧档案，日韩独立 zine 调性。
不要文字，不要水印，不要人脸，不要电影感打光，不要霓虹，
不要 3D 渲染，不要商业广告排版，不要密集拼贴。
```

### 五条要点

1. **说清留白比例和簇的位置。** 别写 "minimal"、"nice"、"somewhere" 这类没有量的词。
2. **一个隐喻，一个物件。** 不要物件清单，不要完整场景。
3. **只有一个高彩度色，并且说清它落在哪个物体上、占多少。**
   其余保持灰度、低饱和 —— 这是整套风格的命门。
4. **一定要写印刷缺陷**：半调、xerox、riso 颗粒、活版压痕、扫描线、套印偏移。
5. **一定要加排除项**（见下面的负面清单）。

### 负面清单（每次都带上）

> 不要文字、水印、人脸特写、logo、CTA、光泽样机、干净 UI 白、电影感打光、
> 3D、霓虹、赛博朋克、可爱风、时尚大片感、密集拼贴、多色混乱、
> 商业广告排版、库存照片写实感、长段文字块。

**不要生成人脸。** 生成的人脸放在生活博主封面上会很怪，读者一眼看出是 AI，掉信任。

## 五种样式

| 样式 | 说明 |
|---|---|
| `zine` ★默认 | 纸纹 + 打字机标签 + 细线 + 不规则锚色块 + 宋体标题 + 侧边微文字 + 套准标记 |
| `zine-pure` | 忠实原版：留白 75%+，字很小，单一小锚 |
| `zine-photo` | 照片装进不出血窗口，去饱和 + 网点 + 锚色油墨叠加 |
| `plain` | 传统大黑字纯色封面。想要冲击力时用 |
| `photo` | 照片全出血 + 底部渐变遮罩 + 大白字。传统做法 |

**默认 `zine`。** 用户明确要冲击力时才用 `plain` / `photo` ——
那两种是通稿感的来源，但有时候确实需要。

## 调色板

用名字就行，也可以直接给 CSS 颜色值。

**纸色 `--tone`**：`warm-white` `ivory`（默认）`light-gray` `old-yellow` `khaki` `kraft`

**锚色 `--accent`**：`cobalt`（默认）`ultramarine` `cyan` `violet` `magenta` `pink`
`lemon` `pear` `orange` `tomato`

**只用一个锚色。** 第二色（`--accent2`）只做套印偏移，必须次要到几乎看不出是第二个颜色。
多色 = 违背整套风格。

**账号一致性**：`--tone` 和 `--accent` 每篇固定下来，主页九宫格会有辨识度。
换色只在换系列时换。

## 渲染器用法

```bash
python skills/xhs-cover/scripts/render_cover.py --title "..." --out cover.png
```

| 参数 | 说明 |
|---|---|
| `--title` | 主标题。`\|` 手动换行，`[方括号]` 上锚色 |
| `--label` | 顶部打字机小标签，如 `travel [03]`。`[]` 内上锚色 |
| `--caption` | 标题下的说明，也支持 `\|` |
| `--micro` | 右侧竖排微文字，如 `kyoto 2026.08` |
| `--sig` | 底部署名，如 `@vivian` |
| `--bg` | 背景图（`zine-photo` 装进窗口；`photo` 全出血） |
| `--style` | 见上表，默认 `zine` |
| `--tone` `--accent` `--accent2` `--ink` | 配色 |
| `--pos` | 内容簇位置：`lower-left`（默认）`upper-right` `center-low` `center-high` `left-middle` `right-middle` |
| `--safe-x` | 左右留白像素 |
| `--title-size` `--title-track` | 字号 / 字距。默认自动算 |
| `--no-grain` `--no-marks` `--no-halftone` | 关掉颗粒 / 套准标记和点群 / 网点 |
| `--from-html` | 跳过模板，直接渲染改好的 HTML |

**字号是自动的**：按最长那行的字数反推，扣掉字距和各样式的额外内缩，保证不折行。
自己指定 `--title-size` 就要自己确认没折行。

依赖：系统里有 Edge 或 Chrome。**Windows 自带 Edge，零安装。**
装在非默认位置就设 `$env:BROWSER_PATH`。

### 微调

每次渲染都会在 PNG 旁边留一份 `cover.html`。想改字距、加装饰、换布局，
直接改这个 HTML，然后：

```bash
python skills/xhs-cover/scripts/render_cover.py --from-html cover.html --out cover.png
```

纸纹和颗粒是 CSS + 内联 SVG 噪声做的，**不依赖任何外部图片**，改起来也方便。

## 封面文字规范

| 项 | 值 |
|---|---|
| 尺寸 | **1080×1440**（3:4） |
| 主标题字数 | **9–13 字**最好读，最多 16 |
| 每行字数 | 5–8 字，用 `\|` 手动断在**语义处** |
| 安全区 | 上下各 8–16%（各样式已处理） |
| 锚色占比 | 全画面 0.8%–2.5%，或视觉簇的 15%–35% |
| 元素数量 | 一个标题 + 一个标签 + 一个锚，别再加 |

断行要断在语义处：
- ✅ `京都下雨那天|我什么都没干`
- ❌ `京都下雨那|天我什么都没干`

## 内页图

一篇最多 18 张。内页图**沿用同一套 `--tone` 和 `--accent`**，划起来才像一个系列。

- **文字卡** —— 换 `--title` 就是一张内页卡
- **序号卡** —— `--label "01"` `"02"`，做成连载感
- **清单卡** —— 改 `cover.html` 加几行，或者一条一张

zine 风格做内页图特别顺 —— 大量负空间 + 一个锚色，天然统一。

## 其他要检查的

- [ ] 用她自己的照片时，图里有没有**其他平台水印**（抖音/快手/B站）→ 判搬运
- [ ] 有没有他人正脸、车牌、门牌号、证件 → 打码
- [ ] 封面文字里有没有违禁词 —— **封面上的字一样会被审核**：
      `python skills/xhs-guard/scripts/xhs_scan.py --text "<封面文字>"`
- [ ] 首图别放纯色无信息的图 —— 首图定点击率
