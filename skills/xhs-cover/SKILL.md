# xhs-cover —— 封面图

## 分工原则（这是这个技能的核心设计）

| 做什么 | 谁做 | 为什么 |
|---|---|---|
| 背景、氛围、场景、质感 | **`image_gen`**（Codex 内置） | 走 ChatGPT 订阅，不需要 API key |
| **中文标题文字** | **本地 HTML/CSS 渲染** | AI 出图写中文经常缺笔画、错字、字距乱 —— 封面标题是要被人读的，不能赌 |

不要让 `image_gen` 直接把中文标题画在图上。生成十次有八次得重来，
剩下两次字距也不对。**背景归 AI，文字归渲染器。**

---

## 三条路线，按需要选

### 路线 A · 纯文字封面（最快，最稳）

不需要 `image_gen`。适合心情型、观点型笔记，也适合手上没好照片的时候。

```bash
python skills/xhs-cover/scripts/render_cover.py \
  --title "京都下雨那天|我什么都没干" \
  --sub "一个人旅行 · 第 3 天" \
  --tag "旅行" \
  --style plain \
  --out drafts/2026-08-13-kyoto/cover.png
```

### 路线 B · 用她自己的实拍照（点击率最高）★ 优先推荐

真实照片的点击率高于任何生成图，**人物出镜的封面点击率平均再高 30–50%**。
她有照片就用照片。

```bash
python skills/xhs-cover/scripts/render_cover.py \
  --title "京都下雨那天|我什么都没干" \
  --bg her-photo.jpg --style photo \
  --out drafts/2026-08-13-kyoto/cover.png
```

### 路线 C · `image_gen` 出背景 + 本地压字

她没有合适照片时用。

**第 1 步**，用内置 `image_gen` 工具生成背景，保存到
`drafts/<日期>-<slug>/cover-bg.png`：

- 尺寸要 **3:4 竖版**。优先 `1152×1536`（3:4 且两边都是 16 的倍数）。
  工具不接受就退到它支持的任意竖版尺寸 —— 渲染器会用 `cover` 裁切，
  比例不对只是裁掉一点边。
- **prompt 里不要写任何要出现在图上的中文文字**。
- 内置工具默认存到 `$CODEX_HOME/generated_images/`，**记得移到 drafts 目录里**。

**第 2 步**，压字：

```bash
python skills/xhs-cover/scripts/render_cover.py \
  --title "京都下雨那天|我什么都没干" \
  --bg drafts/2026-08-13-kyoto/cover-bg.png --style photo \
  --out drafts/2026-08-13-kyoto/cover.png
```

**第 3 步**，把用过的 prompt 存到 `drafts/<日期>-<slug>/imagegen.md`，
方便下次复现或微调。

## image_gen 的 prompt 怎么写

背景图的目标是**给标题让位**，不是自己抢戏。

### 骨架

```
[场景/主体] + [光线] + [色调] + [镜头/质感] + [留白位置] + [排除项]
```

### 例子

```
京都老式民宿的木框窗户，窗外在下雨，窗台上放着一杯焙茶，
柔和的漫射自然光，低饱和的灰绿与暖木色调，
35mm 胶片质感，浅景深，
画面下半部分留出大片简洁的暗区，
不要文字，不要水印，不要人脸特写
```

### 五条要点

1. **明确留白位置。** `photo` 样式的文字在下半部分 → prompt 里就要说
   「下半部分留出简洁暗区」。不然文字会压在杂乱的地方读不清。
2. **低饱和、弱对比的背景更好压字。** 花的背景改用 `band` 样式。
3. **写清光线和镜头。** 「柔和漫射光」「35mm 胶片」比「好看」有用得多。
4. **一定要加排除项**：`不要文字，不要水印，不要人脸特写`。
5. **不要生成人脸。** 生成的人脸放在生活博主的封面上会很怪，
   而且容易被读者认出是 AI，反而掉信任。

## 四种样式

| 样式 | 背景 | 用在什么时候 |
|---|---|---|
| `plain` | 纯色 | 无图、心情型、观点型。**可读性最好** |
| `photo` | 照片 + 底部渐变遮罩 + 白字 | 有好照片，且下部相对干净 |
| `band` | 照片 + 文字垫白色块 | 照片很花、对比强，白字压不住时 |
| `note` | 浅底 + 左侧竖线 | 文字型、日记感、连载系列 |

默认 `plain`。**照片压不住字就换 `band`，不要硬上 `photo`。**

## 渲染器用法

```bash
python skills/xhs-cover/scripts/render_cover.py --title "..." --out cover.png
```

| 参数 | 说明 |
|---|---|
| `--title` | 主标题。`\|` 手动换行，`[方括号]` 上强调色 |
| `--sub` | 副标题，也支持 `\|` |
| `--tag` | 顶部小胶囊标签，如「旅行」 |
| `--sig` | 底部署名，如「@vivian」 |
| `--bg` | 背景图路径 |
| `--style` | `plain` / `photo` / `band` / `note` |
| `--align` | `left`（默认）/ `center` / `right` |
| `--fg` `--bgcolor` `--accent` | 覆盖配色 |
| `--title-size` | 字号。默认按字数自动算，会保证不折行 |
| `--from-html` | 跳过模板，直接渲染改好的 HTML |

**字号是自动的**：按最长那行的字数反推，扣掉各样式的额外内缩，保证塞进安全区不折行。
自己指定 `--title-size` 就要自己确认没折行。

依赖：系统里有 Edge 或 Chrome。**Windows 自带 Edge，零安装。**
装在非默认位置就设 `$env:BROWSER_PATH`。

### 微调

每次渲染都会在 PNG 旁边留一份 `cover.html`。想改字距、加元素、换布局，
直接改这个 HTML，然后：

```bash
python skills/xhs-cover/scripts/render_cover.py --from-html cover.html --out cover.png
```

## 封面文字规范

| 项 | 值 |
|---|---|
| 尺寸 | **1080×1440**（3:4） |
| 主标题字数 | **9–13 字**最好读，最多 16 |
| 每行字数 | 5–8 字，用 `\|` 手动断在语义处 |
| 留白率 | 25–35%，信息才有呼吸感 |
| 安全区 | 上下各留 8%（模板已处理） |
| 元素数量 | 顶多 1 个主标题 + 1 个小标签 |

**断行要断在语义处**，别让渲染器自动折：
- ✅ `京都下雨那天|我什么都没干`
- ❌ `京都下雨那|天我什么都没干`

## 内页图

小红书一篇最多 18 张图。内页图不必都是照片：

- **文字卡** —— 同一个渲染器，换 `--title` 就是一张内页卡
- **清单卡** —— 改 `cover.html` 加几行，或者一条一张
- **对比图** —— 两张照片拼一起（改 HTML 用 flex 排）

内页图**统一用一套配色和字体**，划起来才像一个系列。
`--accent` 和 `--bgcolor` 每篇固定下来，账号会有辨识度。

## 其他要检查的

- [ ] 用她自己的照片时，图里有没有**其他平台水印**（抖音/快手/B站）→ 判搬运
- [ ] 有没有他人正脸、车牌、门牌号、证件 → 打码
- [ ] 封面文字里有没有违禁词 —— **封面上的字一样会被审核**，
