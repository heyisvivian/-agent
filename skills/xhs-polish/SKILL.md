# xhs-polish —— 改稿

判断标准是**好读**（`AGENTS.md` §1.6）。用户原话：
「文采也可以碰 综合而言更好 但是需要比较好读」。

所以文采可以动 —— 用词、句子节奏、断句、段落切分该改就改。
但「好读」不等于「规整」，这是最容易搞混的地方：

> 模型改中文的默认倾向是往**均匀**的方向收 —— 句长拉平、段落对齐、
> 每句都完整。均匀的文本**扫读时抓不住重点**，反而更难读。
> 她那些突然的短句、单行成段、`hh`，是**降低**阅读阻力的，不是增加。

所以第一原则是：

> **改让人卡住的地方，别改让人读得快的地方。**

分模式看「更好」是什么（两个模式的成功指标不同）：

| 模式 | 互动形状 | 「更好」= |
|---|---|---|
| 攻略 / 实操型 | 收藏 ≥ 点赞 | **更好用** —— 步骤清楚、数字全、能存档 |
| 观察 / 思辨型 | 评论 ≈ 点赞 | **更能聊** —— 留接话的口子，别把结论说尽 |

⚠️ 给思辨稿加一个漂亮的收束句 = **压评论**。她的降调结尾就是那个口子。

## 第 0 步 · 读档案，认出这是哪个模式

```
读 profile/voice.md
```

没有档案时不阻塞（AGENTS.md §2 口径）：只做最保守的改动（合规词、明显中文错别字、
超长段落），**不碰任何疑似风格的东西**，改完建议她跑一次 `xhs-voice` ——
没有档案你分不清哪些是她的风格、哪些是这次写岔了。

档案是**分模式**的（A 种草 / B 攻略 / C 生活，见 voice.md）。改稿前先认出
**她这篇写的是哪个模式**，然后只拿那个模式的标准去比。

⚠️ **最容易犯的错**：拿攻略模式的标准去改生活稿或种草稿。
种草罗列稿（A1）常整篇零标点、空格断句 —— 她 2026-08-21 说**「标点是随意的」**，
所以标点按「好读」处理即可、不是禁区；但**行式罗列的结构（一行一件）别改成段落**，
那是这类稿分享率高的原因。

如果这篇的模式在档案里标着 `无样本`，**改动要更保守**：
只改违规和事实问题，风格上的东西先别碰，问她。

## 该改什么，不该改什么

### ✅ 改

| 类别 | 具体 |
|---|---|
| **违规风险** | L1/L2 命中项，必须改（走 `xhs-guard`） |
| **事实问题** | 前后矛盾、时间线错乱、数字不一致 |
| **逻辑断裂** | 缺了必要的一步，读者跟不上 |
| **啰嗦** | 同一个意思说了两遍；形容词堆叠 |
| **结构塌陷** | 开头三行没信息、该分段的地方糊成一坨 |
| **形容词换名词** | 「很好吃」→ 具体的口感/画面（问她要细节，不要编） |
| **格式硬约束** | 标题超 20 字、正文超 1000 字、段落太长 |
| **标签** | 数量不对、有无关标签、缺搜索词 |
| **AI 感** | 「值得一提的是」这类通稿腔（哪怕是她自己写的） |
| **模式混用** | 生活稿里出现攻略模式的分级结构、种草稿被跨模式改，或反之 |
| **超长句** | 逗号连缀到 80 字以上，一口气读不完 —— 断开（A1 罗列稿一行一件的结构保留，别并成段落） |
| **「真的」超过 2–3 次/篇** | 压密度，别删光 —— 她 2026-08-21 要求「压一下 不需要这么多」 |
| **段落过长** | 手机窄屏读不动就拆。段长规格以 voice.md 该模式**已确认值**为准（攻略模式现标「样本不足」，别拿旧统计当规格），未确认就保守拆并问她 |
| **编号跳号** | `1 2 3 4 6 7` 会让读者停下来确认是不是自己看漏了 |
| **重复字 / 语序乱到读不通** | 「拿到了了」；乱到读者要回读第二遍的句子 |
| **拼写错误** | 中英都改（「拿到了了」、`Spotif`→`sportif`、`referal`→`referral`）—— 她 2026-08-21 裁决。`WTHF` 是她的造词不是错拼，保留 |
| **用词** | 换更准、更好读的词 —— 这条按用户 2026-08-20 的口径**放开了** |

### ❌ 不改

| 类别 | 为什么 |
|---|---|
| **口头禅** | 档案里记下来的那些 —— 那是她的签名（下面例子里的「反正」只是示意） |
| **标点习惯** | 她全用句号就别加感叹号；她不用省略号就别加 |
| **句子长短节奏** | 短句连排、单句成段，是节奏不是病 |
| **跳跃的语序** | 只要读得通就别动 —— 口语的语序本来就不规整 |
| **不完整的句子** | 「就，挺好的。」——不要补成完整句 |
| **重复** | 她故意重复的地方（「我就真的没出门。」） |
| **不确定的语气** | 「可能」「说不好」「大概」—— 既真实又合规 |
| **她的判断** | 她说不好吃就是不好吃，不要改成「见仁见智」 |
| **中英混写** | `offer` `ddl` `water一下` —— 对她的读者是降低阻力 |
| **口语标记** | `hh` `Emmmm` `哈哈哈哈` `救命` |
| **降调结尾** | 「说大不大说小不小」—— 那是留给评论的口子 |
| **具体数字和物件** | `8/9个ddl`、`餐桌上无手机` —— 比任何形容词都好读 |

**判断标准**：这处改动让读者读得**更快**，还是只是让文本更**整齐**？
只是更整齐的一律不改 —— 均匀的文本扫读时抓不住重点。

## 步骤

### 第 1 步 · 先扫一遍

```bash
python skills/xhs-guard/scripts/xhs_scan.py --text "<她的原文>"
```

或者把原文存进 `drafts/<日期>-<slug>/note-original.md` 再扫文件。
**留原稿。** 她可能不接受你的改法，得能回退。

### 第 2 步 · 诊断，分级

列出问题，标清等级和是否必改：

```
🛑 必改（违规）
  1. 「私我拿地址」—— L1 站外导流

🔴 建议改（明显拖后腿）
  2. 开头三行是背景交代，信息流只露两行，会被划走
  3. 标题 24 字，超了 4 字会被截断

🟠 可改可不改（看你）
  4. 第三段和第五段说的是同一件事
  5. 标签 9 个，建议收到 5 个以内

✅ 不动（这是你的风格）
  · 「反正」结尾、全句号无感叹号、单句成段 —— 保留
```

**先给诊断，再给改法。** 让她知道你为什么动，比直接甩一版改好的更有用 ——
下次她自己就会了。

### 第 3 步 · 改，且只改诊断里说了的

改的时候：

- **能保留原句就保留。** 只换必须换的词。
- 需要新增细节时（比如「很好吃」要换成具体的），**问她**，不要编。
  ⚠️ 编造细节是造假（`AGENTS.md` 1.2），比啰嗦严重得多。
- 每处改动都要能说出「为什么」。说不出来的就别改。

### 第 4 步 · 给对照，不给成品

用逐句对照表，**不要只给一版改好的全文**：

| # | 原文 | 改成 | 为什么 |
|---|---|---|---|
| 1 | 想要地址的私我 | 店名写在图三了，直接搜就有 | L1 站外导流，执法最严的一类 |
| 2 | 上周我去了京都，天气不太好 | 老板娘端来焙茶，说这种天最好不要出门 | 前两行要给画面，不是交代背景 |
| 3 | 京都下雨那天我在民宿窗边坐了一下午什么都没干 | 京都下雨那天我什么都没干 | 24 字 → 12 字，不会被截断 |

然后给**改后全文**（能直接复制），最后给一句：

> 你的「反正」结尾、不用感叹号、单句成段，我一个字没动。

### 第 5 步 · 重扫

```bash
python skills/xhs-guard/scripts/xhs_scan.py drafts/<日期>-<slug>/note.md
```

跑到 0 个 L1/L2。

### 第 6 步 · 落盘

```
drafts/<YYYY-MM-DD>-<短slug>/
├── note-original.md   # 她的原稿，保留
├── note.md            # 改后
├── diff.md            # 逐句对照表
├── compliance.md
└── checklist.md
```

## 她说「这个改得不像我」的时候

不要立刻再改一版。**先问清楚是哪里**：

> 是哪一句读起来不像？我把那处的改法回退，另外想办法。

然后做两件事：
1. 回退那一处
2. **把结论写回 `profile/voice.md`** —— 这是档案变准的唯一途径

一次「不像我」的反馈，价值大于十篇样本。别浪费。

---

## 一个提醒

如果一篇稿子你想改的地方超过一半 —— 停下来。

那说明问题不在文字，在素材或者选题。
这时候该做的是回到 `xhs-note` 的第 1 步问素材，而不是继续硬改。
把话说清楚给她，别默默重写一篇然后说这是「改好了」。
