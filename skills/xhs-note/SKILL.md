# xhs-note —— 写笔记

用户的原话是「和我语气一样 或者更好 哈哈」。
这个技能的目标不是写出一篇「好的小红书文案」，而是写出一篇**她会认领的**笔记。

---

## 第 0 步 · 读档案，并且**先定模式**

```
读 profile/voice.md
```

没有这个文件时**不阻塞**（AGENTS.md §2 的口径）：按护栏保守值走 ——
不用感叹号堆砌、不升华收尾、保留中英混写和口语标记 —— 写完标出哪几处是
保守处理，并建议她跑一次 `xhs-voice`。**但不要凭感觉猜她的语气**：
模型对「小红书博主」的默认印象是通稿腔。

### ★ 定模式（这一步别省）

档案是**分模式**的（A 种草 / B 攻略 / C 生活）。同一个人写攻略和写生活不是同一套写法 ——
攻略稿里 emoji 当评分刻度（💣🌟）是对的，种草稿里连排同款就成模板号了。

| 这篇是在… | 用哪个模式（对应 voice.md） | 扫描时 |
|---|---|---|
| 讲**她买的东西**，列物件+价格+判断 | **A1 种草·罗列** —— 空格断句、零标点，**别补标点** | `--type short` |
| 讲她买东西的**过程**（本来想→结果→最后） | **A2 种草·叙事** —— 全标点 | `--type life` |
| 讲一件**外部的事**（法规、工具、方法），有信息增量 | **B 攻略模式** | `--type guide` |
| 讲**自己的经历**（去了哪、当时在想什么） | **C 生活模式** | `--type life`（默认） |
| 自己的经历，但目的是给人抄作业（行程、清单） | C + B 的结构 | `--type guide` |

判不准就**问她**。**不要默认套攻略模式** —— 生活内容套上分级结构会很硬。

**攻略模式（B）额外记住：收藏是显式目标。** 她的攻略爆款全靠收藏
（体检藏率 121%、游泳馆 89%、CDI 513 藏），标准是：步骤从头到尾能照做、
价格/时间/地址/入口数字全、时效信息带时间戳、标题能被「城市+事项」搜到。

### 如果这个模式在档案里没样本

档案会明确标 `无样本` 并列出答不了的问题。这时候：

1. **照档案的「临时办法」走**（通常是：继承共同底线、emoji 降到最低、不用另一个模式的结构）
2. **出两版让她选**，并明确说「这个模式我还没有你的样本，这两版哪个更像你」
3. 她一表态，**把结论写回 `profile/voice.md` 对应那节** —— 这是档案变准的唯一途径

## 🛑 两条铁律（2026-08-20 两次实测踩中，写在最前面）

### 一篇只讲一件事

> 「这篇也太乱了吧 分出来很多都可以单独写的 **这篇说存钱就只是存钱就行**」

她笔记里一个选题下面列了 4 条观察，我当成一篇写了 —— 每条都够单独一篇，
塞在一起每条都没讲透。

**素材列了 N 条 ≠ 一篇写 N 条。**
先问「这几条是一篇还是一个系列」。多数情况是系列 ——
而系列比单篇更值：读者会回来找下一集，标题带编号还能形成栏目。

（`xhs-vlog` 早就写着「一个片子只讲一件事」，这条对图文一样成立。）

### 素材不够就停，不要用修辞去填

> 「首先写的不好」

那次只有一行素材（「我爸妈和我男朋友有着同样的存钱理念」），我没问就写了，
结果 165 字里**一个具体的东西都没有** —— 全是「存得比我狠」「那个语气我太熟了」
这种形容。为了把字数撑起来，还写了对偶句和「我学到了」式收尾，
两个都在她的反例清单上。

**空稿的根因不是笔锋不行，是素材不够还硬写。**

对照她自己的写法：`8/9个ddl同时进行` / `一周去2天公司` / `15h飞机` /
`沙子非常细软` / `餐桌上无手机` —— 全是能看见的东西。

所以：**手上没有 2–3 个具体细节（数字、物件、原话、场景）就别开始写。**
去问。问不到就把这个选题放回选题池，明确说「这条素材不够，先放着」——
比交一篇空的好。

## 第 1 步 · 素材够不够

这是最容易出事的一步。**不要替她编经历**（见 `AGENTS.md` 1.2），
**也不要在素材不够的情况下硬写**（见上面第二条铁律）。

拿到想法后，先判断手里有没有这些：

| 必需 | 有 / 没有 |
|---|---|
| 这件事**真的发生过**吗，什么时候 | |
| 至少 2–3 个**只有在场的人才知道的细节** | |
| 她当时的**真实感受**（不是应该有的感受） | |
| 有没有照片/视频素材，几张，拍了什么 | |

细节不够就**问**，不要填。问法要具体，别问「还有什么细节吗」：

- ✅「那家店里当时有别人吗？」「你点了什么，好吃吗还是一般？」
  「有没有哪个瞬间你想拍但没拍下来？」「回去路上你在想什么？」
- ❌「能再多讲讲吗」「还有其他信息吗」

一次问 2–3 个，问完就写。**不要为了信息完整把她审一遍。**

如果她说「你随便写吧」—— 那就写，但把编造的部分用 `⚠️待你确认` 标出来，
明确告诉她哪几句是我替她想的。

## 第 2 步 · 定内容类型

常见的几种，结构不一样（详见 `references/structures.md`）：

| 类型 | 什么时候用 | 结构骨架 |
|---|---|---|
| **片段型** | 一个瞬间、一种心情，没有信息增量 | 状态 → 场景 → 一个具体动作 → 松开 |
| **叙事型** | 有过程、有转折的一段经历 | 起因 → 过程 → 意外 → 现在怎么想 |
| **清单型** | 攻略、行程、物品 | 一句前提 → 3–5 条 → 一句提醒 |
| **观察型** | 看到某个现象想说点什么 | 现象 → 我的反应 → 一点想法（不升华） |
| **对比型** | 之前 vs 现在、期待 vs 实际 | A → B → 差在哪 → 我更喜欢哪个 |

选之前先看**这条线的主指标**（account.md 效率表 v2），再看 `voice.md` 她习惯怎么写：
形态跟着主指标走（攻略线要收藏 → 清单型正是她的收藏爆款形态，别绕开它），
语气按该模式的护栏兜底。两头打架时问她。

## 第 3 步 · 写正文

### 硬约束

- 正文 ≤ 1000 字（生活/旅行 **300–600 字**通常最舒服；她偏短就按她的）
- 每段 ≤ 60 字，段间空一行 —— 手机是窄屏
- 不用 `**加粗**`、不用 `#` 标题（小红书不渲染，会原样显示成符号）
- 换行和空行**就是最终排版**，`note.md` 里的正文要能直接全选复制

### 按档案写

逐项对齐 `voice.md` 里**这个模式**那一节：人称、句长节奏、标点、emoji 密度和用途、
开头套路、结尾套路、段落数。

档案里没写的项 = 还不知道，**按保守值走并标出来问她**，不要凭印象补。

### 三条通用原则（不违背档案的前提下）

1. **具体的名词打败所有形容词。**
   「很好吃」→「面汤上飘着一层油，我先喝了一口」
   「氛围很好」→「那个光是从侧面窗户斜进来的」

2. **前三行决定完读率。** 小红书信息流只露出前两行。
   第一句不要交代背景，直接给一个具体的东西或一个正在发生的状态。

3. **不确定性是加分项。** 「我也说不好为什么」「可能只是那天心情好」——
   这既是真实感，也天然避开了绝对化用语。

## 第 4 步 · 出几版

⚠️ **2026-08-20 起默认只给一版。** 原来的「A 版同款 / B 版进阶」是为
「模仿笔锋」设计的，而她说「不用太细讲究我的笔锋 我也不是文字博主」——
两版同款对照对她没有价值，只是让她多读一遍。

**默认一版，她指哪里改哪里。** 下面的两版做法只在她明确要对比时用：

**A 版 · 同款** —— 完全按 `voice.md`，不做任何"改进"。
她想要的就是这个，这版必须存在。

**B 版 · 进阶** —— 保留她全部的语气特征，只改**一处**结构性的东西。
一次只改一个地方，并且说清改了什么、为什么：

> B 版我只动了开头：原来第一句是「最近总在想旅行要不要把行程填满」，
> 这是一个想法；我换成「老板娘端来焙茶的时候，说这种天最好不要出门」，
> 这是一个画面。信息流只露两行，画面比想法更能让人停住。
> 结尾、句长、标点、你的「反正」都没改。

**不要**在 B 版里塞满优化。她要能一眼看出差别在哪，才谈得上选。
如果两版差别太多，她只会觉得 B 版不像自己。

## 第 5 步 · 标题（给 3 个）

规则见 `references/title-formulas.md`。

- ≤ 20 字（**硬上限**，超了截断），建议 9–16 字
- 要上封面的话 9–13 字最好排
- 前 20 字必须能独立成句
- 三个标题要**风格不同**，不是同一句话换词：
  一个偏画面、一个偏情绪、一个偏信息/搜索词

标题里塞搜索关键词能吃搜索流量，但**不要为了塞词把标题写得不像人话**。
标题特征以 voice.md 当前模式的实测为准（种草模式实测：平均 17.8 字、敢用问句、
品牌名必出现、emoji 只放末尾 1 个）—— 不要引用旧档案的写死数字。

---

## 第 6 步 · 标签（3–6 个）

规则见 `references/tags-seo.md`。

配比：**1–2 个大词 + 2–3 个中词 + 1–2 个长尾词**

```
#京都旅行      ← 大词，流量池大，竞争也大
#一个人旅行    ← 中词，人群精准
#雨天          ← 中词
#京都民宿      ← 长尾，搜索意图明确
```

三条铁律：
1. **每个标签都要和内容真的相关。** 凑无关热门标签 = 蹭流量，判违规。
2. **宁少勿凑。** 3 个精准的比 10 个泛的好。堆标签会被判蹭流量，反压推荐。
3. **一次选对。** 发布后有了流量再改标签容易触发限流。

## 第 7 步 · 强制过审

```bash
# 生活型（默认）
python skills/xhs-guard/scripts/xhs_scan.py drafts/<日期>-<slug>/note.md

# 科普/清单型 —— 正文长度舒适区不一样，别用默认值判
python skills/xhs-guard/scripts/xhs_scan.py drafts/<日期>-<slug>/note.md --type guide
```

**这一步不可跳过**（`AGENTS.md` 第 2 节）。跑完按 `xhs-guard` 的流程做语境裁决、
改写、重扫，直到 0 个 L1/L2。

`--type` 要和第 0 步定的模式一致。用错了会得到没意义的长度建议
（747 字的法规科普被判「偏短需要加长」就是这么来的）。

每版都要扫（默认只有一版）。

## 第 8 步 · 落盘

```
drafts/<YYYY-MM-DD>-<短slug>/
├── note.md          # 正文（frontmatter: title / tags）
├── note-b.md        # B 版（如果出了）
├── compliance.md    # 合规报告
└── checklist.md     # 发布前清单
```

`note.md` 格式：

```
---
title: 京都下雨那天我什么都没干
tags: [京都旅行, 一个人旅行, 雨天, 京都民宿]
---
最近总在想，旅行是不是一定要把行程填满。

……
```

## 交付时说什么

给她的时候，按这个顺序，**不要长篇大论**：

1. 正文（完整贴出来，她要能直接复制；默认一版）
2. 三个标题
3. 标签 + 一句话说为什么选这几个
4. 如果按需出了 B 版：B 版改了哪一处、为什么
5. 合规结论（一行：`✅ 无拦截项` 或 `⚠️ 改了 2 处，见 compliance.md`）
6. 还需要她确认的事（`⚠️待你确认` 的部分、配图张数、AI 声明要不要勾）

## 常见跑偏，自查

写完对着 `voice.md` 的「绝对不是她」清单过一遍。另外：

- ❌ emoji 用法跨了模式（种草=行末单个情绪标点；攻略=💣🌟 评分刻度可连排；别互套，也别凭「她不用 emoji」的旧印象删掉刻度）
- ❌ 结尾升华成金句（「原来旅行的意义不在于走了多远」）
- ❌ 加了她从不写的行动号召（「记得收藏」）
- ❌ 替她编了细节，而且没标出来
- ❌ 为了塞关键词把标题写成 SEO 缝合怪
- ❌ B 版改了五个地方，她根本看不出差别在哪
- ❌ 忘了跑 `xhs-guard`
