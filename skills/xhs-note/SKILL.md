# xhs-note —— 写笔记

用户的原话是「和我语气一样 或者更好 哈哈」。
这个技能的目标不是写出一篇「好的小红书文案」，而是写出一篇**她会认领的**笔记。

---

## 第 0 步 · 先读档案

```
读 profile/voice.md
```

**没有这个文件就先跑 `xhs-voice`。** 不要跳过、不要凭感觉猜她的语气 ——
模型对「小红书博主」的默认印象是通稿腔，直接写出来一定不像她。

---

## 第 1 步 · 素材够不够

这是最容易出事的一步。**不要替她编经历**（见 `AGENTS.md` 1.2）。

拿到想法后，先判断手里有没有这些：

| 必需 | 有 / 没有 |
|---|---|
| 这件事**真的发生过**吗，什么时候 | |
| 至少 2–3 个**只有在场的人才知道的细节** | |
| 她当时的**真实感受**（不是应该有的感受） | |
| 有没有照片/视频素材，几张，拍了什么 | |

细节不够就**问**，不要填。问法要具体，别问「还有什么细节吗」：

- ✅「那家店里当时有别人吗？」「你点了什么，好吃吗还是一般？」
  「有没有哪个瞬间你想拍但没拍下来？」「回去路上你在想什么？」
- ❌「能再多讲讲吗」「还有其他信息吗」

一次问 2–3 个，问完就写。**不要为了信息完整把她审一遍。**

如果她说「你随便写吧」—— 那就写，但把编造的部分用 `⚠️待你确认` 标出来，
明确告诉她哪几句是我替她想的。

---

## 第 2 步 · 定内容类型

生活/旅行赛道常见的几种，结构不一样（详见 `references/structures.md`）：

| 类型 | 什么时候用 | 结构骨架 |
|---|---|---|
| **片段型** | 一个瞬间、一种心情，没有信息增量 | 状态 → 场景 → 一个具体动作 → 松开 |
| **叙事型** | 有过程、有转折的一段经历 | 起因 → 过程 → 意外 → 现在怎么想 |
| **清单型** | 攻略、行程、物品 | 一句前提 → 3–5 条 → 一句提醒 |
| **观察型** | 看到某个现象想说点什么 | 现象 → 我的反应 → 一点想法（不升华） |
| **对比型** | 之前 vs 现在、期待 vs 实际 | A → B → 差在哪 → 我更喜欢哪个 |

选之前看 `voice.md`：她习惯写哪种？如果她从不写清单型，
就算这次素材很适合做清单，也先给她片段型的版本，再问她要不要清单版。

---

## 第 3 步 · 写正文

### 硬约束

- 正文 ≤ 1000 字（生活/旅行 **300–600 字**通常最舒服；她偏短就按她的）
- 每段 ≤ 60 字，段间空一行 —— 手机是窄屏
- 不用 `**加粗**`、不用 `#` 标题（小红书不渲染，会原样显示成符号）
- 换行和空行**就是最终排版**，`note.md` 里的正文要能直接全选复制

### 按档案写

逐项对齐 `voice.md`：人称、句长节奏、标点（她不用感叹号就别加）、
emoji 密度、开头套路、结尾套路、段落数。

### 三条通用原则（不违背档案的前提下）

1. **具体的名词打败所有形容词。**
   「很好吃」→「面汤上飘着一层油，我先喝了一口」
   「氛围很好」→「那个光是从侧面窗户斜进来的」

2. **前三行决定完读率。** 小红书信息流只露出前两行。
   第一句不要交代背景，直接给一个具体的东西或一个正在发生的状态。

3. **不确定性是加分项。** 「我也说不好为什么」「可能只是那天心情好」——
   这既是真实感，也天然避开了绝对化用语。

---

## 第 4 步 · 出两版

针对「和我语气一样 **或者更好**」，默认给两版：

**A 版 · 同款** —— 完全按 `voice.md`，不做任何"改进"。
她想要的就是这个，这版必须存在。

**B 版 · 进阶** —— 保留她全部的语气特征，只改**一处**结构性的东西。
一次只改一个地方，并且说清改了什么、为什么：

> B 版我只动了开头：原来第一句是「最近总在想旅行要不要把行程填满」，
> 这是一个想法；我换成「老板娘端来焙茶的时候，说这种天最好不要出门」，
> 这是一个画面。信息流只露两行，画面比想法更能让人停住。
> 结尾、句长、标点、你的「反正」都没改。

**不要**在 B 版里塞满优化。她要能一眼看出差别在哪，才谈得上选。
如果两版差别太多，她只会觉得 B 版不像自己。

---

## 第 5 步 · 标题（给 3 个）

规则见 `references/title-formulas.md`。

- ≤ 20 字（**硬上限**，超了截断），建议 9–16 字
- 要上封面的话 9–13 字最好排
- 前 20 字必须能独立成句
- 三个标题要**风格不同**，不是同一句话换词：
  一个偏画面、一个偏情绪、一个偏信息/搜索词

标题里塞搜索关键词能吃搜索流量，但**不要为了塞词把标题写得不像人话** ——
她的档案里标题平均 8.3 字且是陈述句，就别给她一个「京都|三日游|超详细攻略」。

---

## 第 6 步 · 标签（3–6 个）

规则见 `references/tags-seo.md`。

配比：**1–2 个大词 + 2–3 个中词 + 1–2 个长尾词**

```
#京都旅行      ← 大词，流量池大，竞争也大
#一个人旅行    ← 中词，人群精准
#雨天          ← 中词
#京都民宿      ← 长尾，搜索意图明确
```

三条铁律：
1. **每个标签都要和内容真的相关。** 凑无关热门标签 = 蹭流量，判违规。
2. **宁少勿凑。** 3 个精准的比 10 个泛的好。堆标签会被判蹭流量，反压推荐。
3. **一次选对。** 发布后有了流量再改标签容易触发限流。

---

## 第 7 步 · 强制过审

```bash
python skills/xhs-guard/scripts/xhs_scan.py drafts/<日期>-<slug>/note.md
```

**这一步不可跳过**（`AGENTS.md` 第 2 节）。跑完按 `xhs-guard` 的流程做语境裁决、
改写、重扫，直到 0 个 L1/L2。

两版都要扫。

---

## 第 8 步 · 落盘

```
drafts/<YYYY-MM-DD>-<短slug>/
├── note.md          # A 版（frontmatter: title / tags + 正文）
├── note-b.md        # B 版（如果出了）
├── compliance.md    # 合规报告
└── checklist.md     # 发布前清单
```

`note.md` 格式：

```
---
title: 京都下雨那天我什么都没干
tags: [京都旅行, 一个人旅行, 雨天, 京都民宿]
---
最近总在想，旅行是不是一定要把行程填满。

……
```

---

## 交付时说什么

给她的时候，按这个顺序，**不要长篇大论**：

1. 两版正文（完整贴出来，她要能直接复制）
2. 三个标题
3. 标签 + 一句话说为什么选这几个
4. B 版改了哪一处、为什么
5. 合规结论（一行：`✅ 无拦截项` 或 `⚠️ 改了 2 处，见 compliance.md`）
6. 还需要她确认的事（`⚠️待你确认` 的部分、配图张数、AI 声明要不要勾）

## 常见跑偏，自查

写完对着 `voice.md` 的「绝对不是她」清单过一遍。另外：

- ❌ 给她加了感叹号 / emoji（她档案里不用）
- ❌ 结尾升华成金句（「原来旅行的意义不在于走了多远」）
- ❌ 加了她从不写的行动号召（「记得收藏」）
- ❌ 替她编了细节，而且没标出来
- ❌ 为了塞关键词把标题写成 SEO 缝合怪
- ❌ B 版改了五个地方，她根本看不出差别在哪
- ❌ 忘了跑 `xhs-guard`
